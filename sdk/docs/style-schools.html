2. Schools
業界主流派對照

大型公司怎麼擺 repo 結構，不是「最佳實踐」一家獨大，而是分成兩大派、底層哲學完全不同。理解兩派差異才能選對自己的。

2.2 兩派的底層哲學

Google/Meta 派：「廠商 vs 我們」是最重要的隔離邊界。
所有廠商東西進 third_party/，build tool（Bazel/Buck）強制 hermetic build。 不 split 是前提（monorepo 哲學）。每個元件依賴明確列在 BUILD file 內。
Lerna/Nx/.NET 派：「元件 vs 元件」是最重要的隔離邊界。
每個 package 自包 code + docs + tests + 廠商 refs，像獨立小 repo 一樣， 未來 npm publish / nuget pack / git split 都自然。

2.3 為什麼會分歧

分歧根源是「monorepo 拆不拆」這個前提：

  • 不拆（Google/Meta）：整個公司一個 repo，元件之間用 build tool 隔離，廠商集中是因為「廠商東西也要被 hermetic build 包進去」
  • 會拆（Lerna/Nx/.NET）：未來某個元件可能變獨立 repo / npm package / NuGet，所以每個元件自包，拆出去時一整包帶走

選哪派的關鍵問句：「3 年後這個 sdk 元件可能變獨立 repo 嗎？」

  • 會 → Lerna/Nx 派
  • 不會 → Google 派（前提是有 Bazel/Buck）
