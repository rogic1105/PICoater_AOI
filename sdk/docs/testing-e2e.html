E2E Manual Checklist
人工點操作 — 真硬體 + 真 UI

1. 為什麼還是要 manual

WinForms 的 UI 互動很難寫穩定的自動化測試（控制項 hierarchy 變動、async paint timing、跨倍率縮放）。 真硬體（PLC / 光源 / 相機）也沒辦法在 CI 環境模擬。

先用「人工 checklist + 結果勾選」確保可重現的驗證 protocol。E2E 同時保留產品 trace，跑 DVT checker 驗證流程與狀態。

2. 驗證紀錄放在哪裡

人工操作步驟與預期行為由對應的 .agents/skills/ 契約管理，不另外維護一份容易過時的 HTML checklist。 執行 E2E 時保留 D:\Anilox\Logs\trace-*.log，再由 tools/python/check_all_flows.py 以及功能專屬 checker 判讀。人工觀察只補充無法從 log 判定的純視覺結果。

3. 寫 checklist 的 case granularity

  • 每個 case 描述一個「使用者明確會做的動作」+「預期結果」
  • 避免複合 case（測 5 件事一次 → 一個 fail 就無法判斷哪件）
  • 保留人能讀的步驟，不要直接寫 code
  • 步驟之間獨立（不要 case B 依賴 case A 的結果）
配合產品 DVT：跑 checklist 時保留 trace，使用 owning skill 的 DVT checker 驗證 intent、順序、token、 狀態快照與禁止行；checker 失敗後再回原始 log 定位，不能只靠人工目視。

4. 跟其他層的關係

Level場景
Unit「按鈕 click handler 邏輯」抽出純函式，Unit 驗證
Integration「click handler → Hub.Set → JSON 持久化」整套
E2E（這篇）「使用者點按鈕 → UI 跟著變 → 硬體真的動」
DVT log checker跑 E2E 後依產品契約檢查 trace，定位流程與時序回歸
