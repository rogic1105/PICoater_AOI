Stress Test
壓力 / Soak — 找跑久才出現的問題

1. 目的

找出「跑久了才會出現」的問題：記憶體洩漏、GC 壓力、效能退化、long-tail latency。 單元測試跑 5 個 case 不會看到的東西。

2. 環境變數控制時長

[Test]
public void PlcCommandLoop_NoMemoryLeak()
{
    int minutes = int.TryParse(Environment.GetEnvironmentVariable("STRESS_MINUTES"), out var m)
                  ? m : 1;
    var deadline = DateTime.UtcNow.AddMinutes(minutes);
    var mock = new Mock<IModbusTcpClient>();
    var ctrl = new IoGrabController(mock.Object) { AutoBackgroundLoop = false };
    long iterations = 0;

    while (DateTime.UtcNow < deadline)
    {
        ctrl.Tick();
        iterations++;
    }

    Assert.That(iterations, Is.GreaterThan(100_000));
    // 配合 dotMemory / PerfView 看 heap，CI 用 STRESS_MINUTES=1 快速跑
}

3. 跑法

場景指令
CI 每次 commit（smoke）STRESS_MINUTES=1
NightlySTRESS_MINUTES=60（1 小時）
Soak（週末）STRESS_MINUTES=1440（24 小時），手動跑單一 [Test]
PowerShell：$env:STRESS_MINUTES = '60'; dotnet test ...

4. 量什麼

  • iterations 數 — 確認跑了多少 cycle（防止 test 早早退出）
  • memory delta — GC.GetTotalMemory(true) before / after，看記憶體有沒有持續成長
  • latency p99 — 收集每 cycle 耗時，計算 p99（找 long-tail）
  • 外部觀測 — dotMemory snapshot 比較 baseline；PerfView CPU sampling 看熱點

5. 不該驗證什麼

Stress test 不該驗證功能正確性。功能正確性是 Unit 跟 Integration 的事。 Stress 只關心「跑久了會不會壞」。
