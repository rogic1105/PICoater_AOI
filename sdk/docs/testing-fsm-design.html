FSM Action Log — Design
用 transition table 把「UI 按下去看起來對」變成可驗證

1. 動機

E2E checklist 的問題：「我點了 chart → 切了 mode → 看起來對」這種「看起來對」沒有客觀標準。 如果改了 click handler 邏輯，使用者點下去畫面看起來一樣但內部 state 跑錯，checklist 也標 ✓。

解法：把 UI state 編成 FSM（Finite State Machine），所有「(action, fromState) → toState」事先列在 transition-table.csv。 runtime 用 logger 記錄真實 transition，跟 table 對比，自動標 ✓ / ❌ / ⚠。

2. 三個檔案 + 一個 viewer

檔案內容寫一次後
state-catalog.csv列出所有可能 state（n 個 setting 組合出 2^n 個 state）新增 setting 才動
transition-table.csv列出所有預期的 (action, from, to)改 click handler 才動
logs/ui-actions-*.jsonlruntime 寫入，每筆一行 JSON每次 E2E 自動產生
viewer.html瀏覽器開，fetch CSV + 拖入或自動載入 jsonl，自動標一次寫好通用

3. state-catalog.csv 範例

state_id,hb_StitchMode,hc_EnableMuraEnhance,hd_EnableReviewEnhance,note
1,Vertical,F,F,預設啟動狀態
2,Vertical,T,F,Vertical + Live 強化
3,Vertical,F,T,Vertical + Review 強化
4,Vertical,T,T,Vertical + 兩邊強化
5,Global,F,F,Global 預設
6,Global,T,F,Global + Live 強化
7,Global,F,T,Global + Review 強化
8,Global,T,T,Global + 兩邊強化

4. transition-table.csv 範例

action,from,to,note
chartMuraVertical.Click,7,1,Global+Review強化 → V (順便關 Review)
chartMuraVertical.Click,1,3,Vertical 點 Review V chart → 開 Review 強化
chartOverview.Click,5,7,Global → 開 Review 強化
chartOverview.Click,3,5,Vertical+Review強化 → Global (順便關 Review)
canvasMain.DoubleClick,1,1,主畫面雙擊 FitToScreen（view-only，無 state 變化）

5. viewer 標記

標記意義
✓ Expected(action, from, to) 在 transition-table — 行為符合預期
❌ Unknown transitionfrom/to 都是 valid state，但組合不在 table — bug 或漏列
⚠ Unknown statestate_id 不在 catalog — setting 組合超出預期範圍
○ View-only純視覺操作（雙擊、拖曳），不改 setting

6. 擴充規則

加新 action（如新按鈕）

在 transition-table.csv 加 row，列出該 action 在每個 state 應該轉到哪個 state。 沒填的 action 跑下去 viewer 標 ❌「unknown transition」自動提示你補。

加新 setting（PG 多一個 bool / enum）

  1. 修改 UiActionLogger.ComputeStateId() — 加新 bit
  2. state-catalog.csv 加新欄位 + 擴充 state 列舉
  3. transition-table.csv 對應新增（舊 row 要更新 from/to 對應新 state_id）
反模式：改 ComputeStateId() 但忘記同步 catalog → 所有舊 row 的 state_id 都對不上，viewer 一片 ⚠。
