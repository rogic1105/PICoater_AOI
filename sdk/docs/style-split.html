6. Split
未來把 sdk 元件拆獨立 repo 的流程

6.1 為什麼能 split 是這套架構的核心

整個 Lerna/Nx 派的設計目標就是「每個元件像獨立小 repo」。 sdk/ 元件 self-contained（code + vendor + docs 在同一目錄）就是為了這天。

但實際 split 之前要先確認元件真的可獨立：

6.2 Split 前的檢查清單

檢查項怎麼確認
沒有反向依賴 src/ grep -r "using AniloxRoll.Monitor" sdk/Bridges/LightBridge/ → 應該 0 hit
沒有跨 sdk/ 元件依賴 看 LightBridge.Core.csproj 的 ProjectReference，不應該指向 ../PlcBridge/ 等
vendor/README.md 寫齊 新 repo 要能獨立理解廠商來源、版本、用途
tests/ 涵蓋率夠 獨立 repo 沒有 src/ 撐著，自己的 test 是唯一保障
README.md 寫齊 public API 未來變 NuGet package 的使用者只看 README

6.3 Split 步驟（用 git subtree）

# 1. 把 sdk/Bridges/LightBridge/ 抽成獨立 git history
git subtree split --prefix=sdk/Bridges/LightBridge -b lightbridge-split

# 2. 推到新 remote
git remote add lightbridge-repo git@github.com:org/LightBridge.git
git push lightbridge-repo lightbridge-split:main

# 3. （可選）從本 repo 刪除，保留 git history 引用
git rm -r sdk/Bridges/LightBridge
git commit -m "split: LightBridge → independent repo"
不刪也可以：保留 sdk/Bridges/LightBridge/ 在本 repo 內，當作「vendored 副本」。 新功能在獨立 repo 開發 + 發 NuGet，本 repo 拉 NuGet 用。 直到下次重大重構才把舊的 sdk/Bridges/LightBridge/ 移除。

6.4 切換引用方式

本 repo 內原本：

<ProjectReference Include="..\..\..\sdk\Bridges\LightBridge\LightBridge.Core\LightBridge.Core.csproj" />

切成 NuGet 後：

<PackageReference Include="LightBridge.Core" Version="1.0.0" />

並設 NuGet feed 為團隊私有 feed（或 GitHub Packages）。

6.5 廠商規格書怎麼處理

Split 後 sdk/Bridges/LightBridge/vendor/ 整包到新 repo。新 repo 通常會：

  • 保留 vendor/：跟著 code 走，新 repo 也能查規格書
  • 升級 vendor/：新 repo 維護者去廠商網站抓最新版替換
  • 移除 vendor/：規格書由廠商網站維護，新 repo 只 keep README.md 寫「規格書見廠商 URL」

選哪個看新 repo 的維護需求。對不會回頭更新的廠商（產品 EOL），保留 vendor/ 最安全。

6.6 split 後本 repo 怎麼維護

  • 本 repo 的 sdk/<元件>/ 變成「拉 NuGet 的引用點」，不再放 code
  • sdk/docs/（本目錄）留下 — 其他 sdk/ 元件還會用
  • 下次新增 sdk/ 元件時，仍然走 self-contained 流程，未來再 split
