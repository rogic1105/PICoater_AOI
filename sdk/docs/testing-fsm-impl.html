FSM Action Log — Implementation
UiActionLogger.cs + viewer.html 實作細節 + 已知坑

本篇承接 FSM Design — 那邊講「為什麼」+「CSV 格式」，這邊講「怎麼實作」+「踩過的坑」。

1. Runtime logger（C# 端）

核心類：UiActionLogger。三個 API：

UiActionLogger.SetSource("chartReviewVertical.Click");  // click handler 開頭
UiActionLogger.OnSettingChanged(c);                   // SettingsHub.Changed 訂閱
UiActionLogger.RecordViewOnly("camReviewMain.DoubleClick"); // 純視覺操作

2. ComputeStateId() 設計

用 bit 編碼把 n 個 bool / enum 壓成單一整數 + 1：

public static int ComputeStateId()
{
    int b0 = _settings.StitchMode == StitchMode.Global ? 4 : 0;  // bit 2
    int b1 = _settings.EnableMuraEnhance  ? 1 : 0;               // bit 0
    int b2 = _settings.EnableReviewEnhance ? 2 : 0;              // bit 1
    return b0 + b1 + b2 + 1;  // 1..8 (1-indexed 給人看比較直觀)
}

public static void OnSettingChanged(SettingChange c)
{
    if (!Enabled) return;
    int newState = ComputeStateId();
    int realBefore = ComputeStateBefore(c);  // 見 §4 SetBatch 修法
    if (realBefore != _lastStateId)
    {
        // 補一筆 (batch) entry
        _queue.TryAdd(BuildJsonl(source, "(batch)", null, null,
                                 _lastStateId, realBefore, "Batch"));
        _lastStateId = realBefore;
    }
    _queue.TryAdd(BuildJsonl(source, c.Name, c.OldValue, c.NewValue,
                             _lastStateId, newState, c.Source.ToString()));
    _lastStateId = newState;
}

4. ★ 已知坑：SetBatch 不 raise event → 假 ❌

場景：SettingsHub 有 SetBatch（一次改多個 setting、不 raise event 避免 race），logger 收不到變更，_lastStateId 不更新。下次 Set 觸發時 stateBefore 是 stale 值，viewer 誤標 ❌。

實際案例（2026-05-21 抓到）：

10:14:15.877  chartReviewPatch.Click       hd F→T  5→7   ✓
10:14:18.431  chartReviewVertical.Click   hd F→T  7→3   ❌ 假錯誤！

真相：state 7 點 chartReviewVertical 觸發 SwitchReviewStitchModeAndDisableEnhance，內部 SetBatch 改 hb=Vertical + hd=False 但不 raise event → state 真的是 7→1，logger 沒記。 使用者接著第二次點 chartReviewVertical（state 已是 1）→ Hub.Set(hd, true) → 1→3。 logger 看到 stateBefore=7（stale），寫成「7→3」假錯誤。

修法：ComputeStateBefore reverse trick

private static int ComputeStateBefore(SettingChange c)
{
    try
    {
        var prop = typeof(InspectionSettings).GetProperty(c.Name, ...);
        if (prop == null || !prop.CanWrite) return ComputeStateId();
        prop.SetValue(_settings, c.OldValue);   // 暫時 reverse
        int s = ComputeStateId();
        prop.SetValue(_settings, c.NewValue);   // 還原
        return s;
    }
    catch { return ComputeStateId(); }
}

進入 OnSettingChanged 時 _settings 已被 c 改過。暫時 reverse c.Name 屬性到 c.OldValue 算 state，再還原。 比對 realBefore vs _lastStateId 不一致就補 (batch) entry。

5. 已知 limitation：最後一個 SetBatch

修法只能在「下次有 raise event」時補上。如果 SetBatch 是最後一個動作（之後沒人 Set），永遠不會補。 實務影響低（連續操作中下次必補），根治需要 Hub.SetBatch 加可選 raiseAggregate 參數。

6. 開關設計（Production 零 overhead）

在 InspectionSettings 加 [Browsable(false)] DebugUiActionLog 預設 false。runtime check：

public static void SetSource(string source)
{
    if (!Enabled) return;  // 預設 Enabled=false，整條 path 直接 return
    _currentSource.Value = source;
}

Production 不啟用，純 dev mode 開。

7. ⚠ SetSource 覆蓋不全 → batch 收屍

目前只覆蓋 8 個 chart/canvas handler。tabControl / cb / btn 系列 click 沒加 SetSource，內部 SetBatch 改 setting 後，logger 看不到，等下個有 SetSource 的 click 進來時 batch detection 補 entry，但 source 標到「碰巧下一個」action 上（「收屍」現象）。

實際看 log 出現 (batch) X→Y, source=某 chart.Click 時，先懷疑：X→Y 不是這個 chart click 造成的，是中間沒覆蓋的 control 造成。 要根治：補全 SetSource 到所有改 setting 的 control（~10-15 處），或在 Hub.Set/SetBatch 內 stack trace 自動推斷 source。
