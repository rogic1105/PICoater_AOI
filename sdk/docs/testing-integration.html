Integration Test
含檔案 IO、JSON round-trip、mock 硬體

1. 目的

驗證「多元件協作 + 邊界 IO」是否正常。允許檔案 IO、JSON round-trip、CSV 寫入、mock 硬體。 不允許真硬體連線（那是 E2E）。

2. 跟 Unit 的差別

差異UnitIntegration
速度< 5ms< 1s（含 temp file 建立 / 寫入）
CI 跑時機每次 commitPR / nightly
依賴純記憶體檔案系統、process
失敗除錯確定性，重跑必同結果可能跟磁碟、權限有關

3. 範例：JSON Save/Load round-trip

[Test]
public void InspectionSettings_RoundTrip_PreservesAllFields()
{
    var temp = Path.GetTempFileName();
    try
    {
        var original = new InspectionSettings
        {
            Recipe = { HessianMaxFactorV = 0.5f, ErrorValueMeanV = 0.3f },
            Storage = { AniloxRootPath = @"D:\Test\Anilox" },
            // ...
        };
        InspectionSettingsStore.SaveToPath(original, temp);
        var loaded = InspectionSettingsStore.LoadFromPath(temp);

        Assert.That(loaded.Recipe.HessianMaxFactorV, Is.EqualTo(original.Recipe.HessianMaxFactorV));
        Assert.That(loaded.Storage.AniloxRootPath,    Is.EqualTo(original.Storage.AniloxRootPath));
        // 所有欄位逐一驗證
    }
    finally { File.Delete(temp); }
}

4. 典型適用場景

  • JSON / CSV 序列化 round-trip — 確認 Save → Load 還原所有欄位
  • 檔案 schema 演進 — 加新欄位後舊 json 仍能讀，default value 補上
  • 多元件協作 — Hub.Set → save disk → load 確認持久化
  • Mock 硬體 — Unit 也做，但 Integration 可以加上「實際 socket 行為」（如 localhost TcpClient）
cleanup 重要：每個 test 用 Path.GetTempFileName() 拿臨時檔，try/finally delete。 不要寫到固定位置（會跟其他 test race）。
