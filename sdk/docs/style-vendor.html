5. Vendor
vendor/ 子目錄規則 + README 模板

5.1 標準子目錄

子目錄內容必要？
vendor/README.md廠商名、版本、來源、用途、最後更新★ 必要
vendor/manual/廠商規格書 PDF / 操作手冊有就放
vendor/samples/廠商示範程式（C++ / .NET / Python...）有就放
vendor/headers/廠商 header files（#include 用）有就放
vendor/binaries/廠商預編譯 dll / lib有就放，注意 .gitignore
vendor/LICENSE.txt廠商授權文件有就放（合規）

5.2 多廠商怎麼分

當一個 sdk/ 元件對應多個廠商 SDK（如 sdk/Grabber/ 同時包 Matrox Grabber 跟 Matrox CLProtocol），用子子目錄區分：

sdk/Grabber/vendor/
├── README.md                   總說明，列出兩個子 SDK
├── matrox-grabber/
│   ├── README.md               這個子 SDK 的細節
│   ├── manual/
│   └── samples/
└── matrox-clprotocol/
    ├── README.md
    ├── manual/
    └── samples/

5.3 vendor/ 內絕對不改

反模式：在 vendor/ 內直接修改廠商 sample code「順便 fix 一個 bug」。 這樣做廠商發新版時 diff 沒法乾淨 merge。
正確做法：
  • vendor/ 內保持原樣（追廠商更新時整包替換）
  • 需要改的話複製到 sdk/<元件>/<元件>.Core/ 內變成「我們的 code」，diff 改在那邊
  • 在 <元件>.Core/ 的 code 加 comment 標「// based on vendor/samples/foo.cpp §3.2」

# LightBridge

LTS-3DPA24 光源控制器 .NET wrapper。RS-232 通訊，支援 AutoDetect COM port。

## Layout
- `LightBridge.Core/` — 純 .NET library，無 GUI 依賴
- `vendor/` — 廠商規格書 + 範例（不參與 build，純參考）

## Public API
- `LightController.AutoDetect()` — 掃描所有 COM port 探測
- `LightController.TurnOn()` / `TurnOff()`
- `LightController.SetBrightness(0-255)`

## Dependencies
- .NET Framework 4.8
- System.IO.Ports

## Vendor reference
- 廠商：LTS（Linkpark Technology Suzhou）
- 型號：3DPA24 系列控制器
- 規格書：`vendor/manual/`
- DEMO：`vendor/samples/`
