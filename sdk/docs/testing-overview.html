Testing Overview
為什麼需要四層測試 + DVT log checker

1. 金字塔

DVT log checker（執行期行為契約）
E2E Manual Checklist（人工點操作）
Integration（含檔案 IO / mock 硬體）
Unit（純邏輯 / 無外部依賴）

傳統金字塔只有底下三層。DVT log checker 是新增層——把「使用者 intent → async 流程 → 顯示/資料狀態」變成可驗證的 code-flow + log-flow 契約，補上 E2E 難以自動覆蓋的實機時序。

2. 對照表

層速度覆蓋適合驗證不適合驗證
Unit< 5ms / case純函式、Hub.Set 邏輯、CSV 解析、FSM 邏輯 輸入→輸出的決定性轉換UI 顯示、檔案 IO、time-based
Integration< 1s / caseJSON Save/Load round-trip、CSV 寫入、IoGrabController FSM + mock IModbusTcpClient 多元件協作 + IO 邊界UI 互動、長時間
Stress數十秒~數小時100 萬筆 Hub.Set / 50 萬 CSV、Soak 24h、IO FSM 連續循環 記憶體洩漏、效能退化、長時間穩定功能正確性
E2E Manual數分鐘 / 全套主畫面點 chart → mode 切換、PG 改值流程、IO 取像 UI 跨控制項聯動、跨倍率顯示、硬體串接邊界值、回歸測試自動化
DVT log checker跑 E2E 後分析 traceintent、順序、token、快照與禁止行 行為契約回歸與故障定位純函式邊界值

3. 關鍵原則

往金字塔上爬，每層成本變高（速度慢、撰寫貴、維護難）。所有能放下層的測試都放下層。
新功能寫測試的問句順序：「這條測試需要設定外部資源（檔案 / mock 硬體）嗎？」→ 是 → Integration ｜ 「會跑很久（> 1s）嗎？」→ 是 → Stress ｜「都不是」→ Unit。
