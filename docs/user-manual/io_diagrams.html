0. IoState Enum 對照表

Enum原名中文說明DO 輸出
IoState.DisconnectedInitial未連線 尚未連線或連線失敗，背景重連中全 LOW
IoState.IdleReady待機 已連線，等待 DI_INSPECT_START 上升緣PC_ALIVE=1
IoState.RunningRun取像中 Grab 執行中，等待停止或瑕疵PC_ALIVE=1, BUSY=1
IoState.StoppingStop停止中 過渡態：清除 MURA/BUSY 後回 Idle(過渡)
IoState.FaultedDevOff設備離線 DI_NAKAN_ALIVE 消失（設備未開機/斷線），保持 PC_ALIVE 等恢復PC_ALIVE=1
IoState.CommLostPCErr通訊中斷 TCP 例外，釋放連線，背景重連全 LOW (連線已斷)
IoState.ClosedClosed已關閉 明確呼叫 StopAsync() 關閉全 LOW

2. UML Sequence Diagram 訊息序列圖（含連線媒介）

藍色 = Modbus TCP 訊息（IPC ↔ ET-7044，FC2 讀 DI / FC5 寫 DO）· 橙色 = DI/DO 電氣信號（ET-7044 ↔ Nakan）· 虛線 = return 回覆封包 · 紅色 = 錯誤路徑

圖中術語白話說明
ConnectAsync(IP, 502) 程式透過網路連線到 ET-7044 模組。IP 是模組的網路位址（預設 192.168.255.1），502 是 Modbus 通訊的固定 port 號
TCP 三向交握 網路連線建立前的「確認彼此都在」程序 — 電腦先喊「我要連」，模組回「收到，我也準備好」，電腦再回「OK 開始」。三步完成後才算連線成功
FC2 Read DI Modbus 指令碼 2 號 — 「讀取輸入」。程式每 500ms 用這個指令問 ET-7044：「現在 DI 腳位的狀態是什麼？」
FC5 Write DO Modbus 指令碼 5 號 — 「寫入輸出」。程式用這個指令命令 ET-7044：「把某個 DO 腳位設成 HIGH 或 LOW」
return DI[0]=1, DI[1]=0 ET-7044 回覆 FC2 的結果。DI[0]=1 代表 DI_NAKAN_ALIVE 是 HIGH（設備有開機），DI[1]=0 代表 DI_INSPECT_START 是 LOW（還沒按啟動）
EnterIdle() 程式內部動作：連線成功且確認設備存在後，狀態從「未連線」切到「待機」，同時送出 PC_ALIVE 信號告知設備「我準備好了」

4. SFC — Sequential Function Chart 順序功能圖 (IEC 61131-3)

S0 — Disconnected 未連線
N: StartAsync(ip, port) 嘗試連線
N: ReconnectTimer ← 5s interval 背景重連
T0: ConnectAsync() == OK 連線成功
S1 — Idle 待機
N: DO PC_ALIVE ← HIGH   PC 存活信號
N: DO MURA ← LOW     清除瑕疵信號
N: DO PC_BUSY ← LOW    清除忙碌信號
N: _lastDiStart ← false    重置邊緣偵測
N: PollTimer.Start(500ms)   開始輪詢
T1: DI_INSPECT_START ↑ rising edge 上升緣 AND State == Idle
S2 — Running 取像中
P1: OnStartRequested → 觸發 Grab 開始
N: DO PC_BUSY ← HIGH   忙碌信號
T2a: meanPeak > ErrMean 均值超標
OR maxPeak > ErrMax 峰值超標
※ 【暫停檢測】啟用時此轉移被抑制
S3 — MURA 瑕疵
P1: DO MURA ← HIGH   瑕疵信號
N: 保持 PC_BUSY = HIGH Keep BUSY
T3: DI_INSPECT_START ↓ falling edge 下降緣
T2b: DI_INSPECT_START ↓ falling edge 下降緣
(無瑕疵 no MURA)
S4 — Stopping 停止中
P1: OnStopRequested → 觸發 Grab 停止
N: ClearMura → DO MURA ← LOW 清除瑕疵
N: DO PC_BUSY ← LOW     清除忙碌
T4: Cleanup complete 清除完成
↑ 回到 S1 Idle 待機 / Return to S1
S5 — Faulted 設備離線
P1: DO MURA ← LOW    清除瑕疵 Clear MURA
P1: DO PC_BUSY ← LOW   清除忙碌 Clear BUSY
P1: OnStopRequested    緊急停止 Emergency stop
N: 保持 PC_ALIVE = HIGH   Keep PC alive
N: 持續 Polling      Continue polling
T5: DI_NAKAN_ALIVE restored 設備信號恢復
→ 回到 S1 Idle / Return to S1
S6 — CommLost 通訊中斷
P1: _plc.Dispose()     釋放 TCP Release TCP
P1: OnConnectionChanged(false) 通知 UI
P1: OnStopRequested     緊急停止 Emergency stop
N: ReconnectTimer ← 5s   背景重連 Auto reconnect
T6: ReconnectAsync OK 重連成功
→ 回到 S1 Idle / Return to S1
SFC 動作限定符 Action Qualifiers — N: 非儲存 Non-stored (持續執行 continuous)  P1: 上升脈衝 Pulse rising (進入時執行一次 execute once on entry)

5. Grab 控制與光源聯動架構

IO 與手動兩條路徑都匯入同一個 btnLiveGrab_Click()，光源開關統一在按鈕邏輯內處理，不依賴觸發來源。

觸發源開始抓取停止抓取btnLiveGrab 狀態
IO 已連線（正常） DI_INSPECT_START ↑ → PlcStartGrab → btnClick → LightTurnOn DI_INSPECT_START ↓ → PlcStopGrab → btnClick → LightTurnOff Disabled「IO 控制中」藍底
IO 未連線 / IO 暫停 手動點按鈕 → btnClick → LightTurnOn 再點一次 → btnClick → LightTurnOff Enabled 正常可點擊
IO 暫停（_isIoSuspended） PlcStartGrab / PlcStopGrab 直接 return，IO DI 訊號被忽略 Enabled 手動控制

6. IO 暫停模式 — lblIoConn 點擊切換

點擊狀態列的 IO 連線燈即可暫停 IO 控制（軟體層旗標），PLC TCP 連線與 keepalive DO_PC_ALIVE 保持不變。再點一次恢復。

項目正常（IO 已連線）暫停中（_isIoSuspended）
lblIoConn 外觀綠底白字「● IO 已連線」黃底黑字「● IO 暫停 ⏸」
btnLiveGrabDisabled「IO 控制中」藍底Enabled 可手動點擊
PlcStartGrab / PlcStopGrab正常執行直接 return，DI 觸發無效
TCP 連線維持維持（不斷線）
DO_PC_ALIVE keepalive持續輸出 HIGH持續輸出 HIGH
UpdatePlcConnectionUi callback正常更新 UI直接 return，不覆寫暫停狀態
UpdateStandardBgSubLockStateIO 連線守衛：不覆寫 Enabled守衛解除，可正常管理 Enabled

典型使用場景：現場調機時需要手動控制取像，但不想真正斷開 IO 連線（避免設備誤判 PC 離線）。
