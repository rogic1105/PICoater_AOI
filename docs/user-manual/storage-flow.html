1. 雙機架構總覽

兩台機器執行同一個 AniloxRoll.Monitor.exe，由 Config/app-mode.json（部署時寫入）決定功能範圍。若檔案不存在 → 預設 Inspection mode。

🖥 檢測機（Inspection mode）

  • 存檔根目錄：D:\AniloxCaptures\
  • 最少剩餘空間：LocalMinFreeGB（預設 100 GB）
  • 遠端路徑：\\192.168.10.20\AniloxStorage
  • 遠端 Config：\\192.168.10.20\AniloxConfig

  • 即時監控（Live tab）
  • 歷史查詢 / 檢測報表
  • 全部設定（PropertyGrid）
  • MIL 相機 / GPU / PLC / 光源
  • RemoteCopyService（佇列→複製）
  • StorageRetentionService（事件觸發）
⇄ SMB
1 Gbps 📄 cleanup-request.flag
→ AniloxConfig

🗄 儲存機（Storage mode）

  • 存檔根目錄：D:\AniloxStorage\（本地路徑）
  • 最少剩餘空間：各自獨立設定
  • RemotePath：空（不往外複製）

  • Live tab（隱藏）
  • 歷史查詢 / 檢測報表
  • 全部設定（PropertyGrid，同 Inspection）
  • MIL / GPU / PLC / 光源（完全跳過）
  • RemoteCopyService（不啟動）
  • StorageRetentionService（Polling 觸發）
  • 狀態列顯示「Storage 模式」
⚠ PropertyGrid：兩機顯示相同設定項目（不動態隱藏，簡化實作）。儲存機的 Camera / IO / Light 設定值不影響任何執行路徑，因硬體初始化已被跳過。

IHardwareInitializer 介面隔離（Storage mode crash 防護）
  • 定義 IHardwareInitializer 介面，包含 Camera / PLC / 光源 init 方法
  • Inspection mode：注入 RealHardwareInitializer（現有 init 邏輯）
  • Storage mode：注入 NullHardwareInitializer（全部 no-op）
  • 新增硬體 init 路徑時，強制在 NullHardwareInitializer 加空實作 → 開發者必須意識到 Storage 分支
    • Deploy 腳本更新點（deploy/）
    • storage-pc/install.bat：首次部署並寫入 Config\app-mode.json（Storage mode）
    • inspection-pc/install.bat：首次部署並寫入 Config\app-mode.json（Inspection mode）
    • storage-pc/storage-config.json：補充 AppMinFreeGB、AppCaptureRootPath 欄位

    5. 循環儲存（事件驅動，無 Timer）

    觸發時機設計

    檢測機觸發點

    • 【停止抓取】按下（btnLiveGrab 停止）
    • 每幀完成後：每累積 10 次 grab 寫一次 flag
    • Grab 異常：距上次 grab 完成 > 30 秒仍在運行 → 觸發一次
      正常 grab ≈ 10 秒；超過 30 秒代表卡住或異常
    • App 啟動時執行一次（Startup recovery）

    儲存機觸發點

    • Polling 60 秒掃描一次 AniloxConfig\cleanup-request.flag
    • 找到 flag → RunCleanup() → 刪除 flag（ACK）
    • App 啟動時掃描殘留 flag 並補跑（Recovery）
    • App 啟動時執行一次 RunCleanup()（上次未清理補收）

    Polling 比 FileSystemWatcher 更可靠：高 I/O 時 FSW 內部 buffer 可能溢出導致漏報；Polling 不依賴事件通知。

    6. 連線狀態回報（lblStorageConn）

    lblStorageConn 已實作（Designer.cs 完整），每 500ms tick → 每 2 秒背景 probe。

    Inspection mode（現行）

    • 背景 Task：先探 TCP 445，再於 RemotePath 建立、寫入、flush、刪除唯一探針檔
    • 分享可寫且 heartbeat 新鮮 → ● 儲存電腦 已連線
    • 分享可寫但程式未回報 → ● 儲存分享可用 / 程式未回報
    • 離線 → ● 儲存電腦 離線
    • 停用（RemotePath 空）→ ● 儲存電腦 停用
    • probe 進行中 → 保留上次顯示（null 不更新）

    Storage mode（現行）

    • 不 probe（RemotePath 為空，App 也不往外連）
    • 啟動後固定顯示：● Storage 模式
    • 每 5 秒原子更新 Config\storage-app-heartbeat.json
    • 其餘硬體狀態列（PLC / 光源）隱藏

    Storage mode 不載入 MIL，也不初始化相機、IO 或光源。
